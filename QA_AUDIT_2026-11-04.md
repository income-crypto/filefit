# Filefit deep QA and growth audit — 4 November 2026

**Production:** https://file-fit.pages.dev/  
**Source:** `income-crypto/filefit`, Cloudflare Pages project `file-fit`, branch `main`  
**Audit approach:** Read the production repository and config, Cloudflare Pages deploy records, Cloudflare Web Analytics SQL data, and live site HTML. Exercised normal browser image-resize flow and simulated file-limit edge cases. Some full browser interaction tests could not complete because the independent testing service exhausted its concurrent browser sessions; those tests are explicitly marked unverified.

## Executive assessment

The live production Pages deployment was successful at audit time. Cloudflare Web Analytics is collecting beacons, and live homepage, tools, blog, guide and privacy pages returned 200 with Cloudflare and GA4 scripts present. Most recorded activity is still homepage traffic with missing external referrers, so **organic growth is not yet established**. The two most actionable code problems are (a) unbounded local file size and batches causing browser memory failures, and (b) lack of tool completion/error signals in opt-in GA4. These are addressed in PR #17 along with a build smoke suite.

### Confirmed findings and changes

| Priority | Finding / evidence | Action |
|---|---|---|
| P1 | Uploads accepted arbitrarily large images/PDFs and unlimited batch counts in `app.js`. Canvas encoding and PDF embedding are memory intensive on mobile. | **Fixed in PR #17.** Reject zero-length and oversized files, cap each image at 50 MiB, each PDF at 80 MiB, batch at 20 files / 150 MiB total, and decoded image at 40 megapixels. Communicate limits at upload controls. |
| P1 | Tool switching or file replacement was allowed while a long conversion was processing, creating risk of an output appearing in an unrelated workspace. | **Fixed in PR #17.** Block switching/replacing files during processing and show a clear error state. |
| P2 | No GA4 conversion outcome events: the site could count pageviews without showing which tool succeeded or failed. | **Fixed in PR #17.** When GA4 is already enabled, emit `filefit_tool_start`, `filefit_tool_complete`, `filefit_tool_error` with **only** a fixed, public `tool_id`. No file names, contents, dimensions or error messages leave the browser through these events. Updated privacy policy. |
| P2 | No build-time regression test for the site's 17 sitemap pages, verification tags, bundled PDF library, and ad-disabled state. | **Fixed in PR #17.** New `qa-smoke.mjs` runs during Cloudflare Pages build. It checks 17 page paths, meta verification, one GA4 preference script per page, sitemap links, JS syntax, exact vendor PDF file, safety guards, and both ad networks disabled. |
| P2 | GA4 dashboard looked empty. Current implementation only starts after region policy or affirmative choice; Cloudflare recorded only 5 pageviews from India for the period, and most events were from other countries. | **Identified; not a proven site malfunction.** Clean browser previously sent `g/collect` successfully; GA4 account reporting still needs validation in Realtime/Data Streams. The region policy is India automatic only; international opt-in is expected. |
| P2 | Cloudflare Web Analytics had recorded only homepage events. Homepage tool cards run the tools within `/`; clicking those cards does not navigate to dedicated tool URLs. | **Product analytics limitation.** GA4 tool-use events now capture successes when permitted. Dedicated pages exist for SEO, but promotion and discoverability remain priorities. |
| P2 | Infolinks account awaited ownership verification; exact assigned code is currently in an inactive HTML `<template>`. Provider might not accept inert markup as verification. | **Pending provider.** Do not misrepresent approval; ask Infolinks support whether consent-gated verification is accepted, and do not automatically activate advertising. |
| P3 | Cloudflare RUM site's `host` configuration is a broad regex-like string `(file-fit.pages.dev)$` without a start anchor or escaped dots. | **Review rather than blind update.** Actual audited events matched only the intended production hostname, so no confirmed data pollution; tightening this may require provider confirmation. |
| P3 | Cloudflare Worker builds named `filefit` have failed intermittently, whereas **Cloudflare Pages `file-fit` production and previews were successful**. | **Separate project**. Do not modify the unrelated Worker blindly. If unused, audit its CI trigger to reduce distracting alerts. |

### Function and site checks

- **Production Pages deploy:** success; latest audited branch `main` commit `bb9a46106fcd6a99cf6ad4b46a6b0372477f23b7` (before PR #17).
- **Accessible routes:** homepage, image compressor, merge PDF, blog, upload guide, privacy all responded 200.
- **Cloudflare beacon and GA4 preference tag:** present on homepage, tool pages, blog, guides and privacy.
- **CSP and security headers:** CSP, X-Content-Type-Options, Referrer-Policy and anti-framing restrictions in `_headers`.
- **Canonical and sitemap:** static sitemap includes 17 useful URLs, six individual tool pages and five guides. `robots.txt` allows indexing and points to sitemap. A static SEO audit is not a confirmation of Google indexing.
- **Image resizer:** normal sample PNG → output 413×531 JPG succeeded in the live browser test (2.8 KB output for synthetic sample).
- **Browser regression tests:** native 375px-width layout for GA4 and website controls was previously tested without horizontal overflow.
- **PDF conversions:** bundled `pdf-lib.min.js` returns an HTTP 200 and is >500 kB; however the live browser harness could not reliably confirm the global `PDFLib` from a dynamically injected script. **Do not label PDF conversion fully tested.** Run a real PDF upload/merge/split in Chrome before claiming feature coverage. No code change to vendor library was made.
- **AdSense & Infolinks:** AdSense site still pending review as last verified, Infolinks still pending verification. No live ad network was activated.

### Near-term growth opportunities

1. **Measure actual conversions**: use the new opt-in GA4 start/complete/error events together with Cloudflare aggregate page loads. Before more marketing spend, verify GA4 Realtime and exact measurement ID in the Google property.
2. **Improve legitimate discoverability**: inspect Google Search Console coverage and indexed URL status for six dedicated tool pages and five guides. Re-submit sitemap only if useful, and resolve any Google-reported indexing reason; do not claim indexing solely from HTTP 200.
3. **Promote direct landing URLs**: for photo/signature KB requirements and PDF tools, link relevant individual tool pages from accurate tutorials, community replies where permitted, and approved directory listings. Avoid artificial visits and backlink spam.
4. **Use real-life test fixtures**: test transparent signature PNG, large photo, small 20 KB target, image-to-PDF, two PDF merge, and split PDF with an invalid range, on Safari and Android as well as Chrome.
5. **Watch deployments and errors**: preserve Cloudflare Pages `main` as release source; distinguish the unrelated Worker build from Pages production health. Review Web Vitals once the site has meaningful visits.
6. **Delay ads until approval**: preserve usability around file inputs, check CMP/privacy and Infolinks format settings, and compare engagement/SEO after ads rather than blindly enabling overlays.

### Scope limits / explicit non-findings

- The analytics account's raw GA4 reports and Google Search Console coverage were not accessible through the connected Cloudflare and GitHub apps. No claims about indexed page totals, search impressions or GA4 report filters were independently verified.
- User-file privacy was reviewed from code paths; this is not a penetration test, formal legal compliance audit, cross-browser certification, or guarantee no tracking extension alters behavior.
- No real user uploads, external payments, ad impressions or destructive security tests were run.
